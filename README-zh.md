# dsh-memory

[English](README.md) | 中文

**你的经验，它看得见。** 一个 markdown 笔记目录变成 agent 的记忆——不用向量、不起服务、没有排名模型。
agent 自己读索引，自己决定打开哪一条。

**诚实的版本：** 它让一个整理过的笔记本**对 agent 可见**，并且能**写回去**。它做不到可靠地**替你记住**。
在这位作者自己的笔记本上实测，用笔记本里没有的说法提问，能召回到正确条目的比例大约是**五分之一**。
装之前请先读[它有多准](#它有多准)——这一节是绝大多数记忆项目会省掉的部分。

## 要解决的问题

每个会话都是从零开始的。那些当初花了力气才搞明白的东西——长路径就崩的工具链、谎报自己设置的驱动、
悄悄写进错误环境的安装器——下次照样要重新学一遍，代价一样。

已有的两种做法，都是拿一个问题换另一个：

- **向量库和记忆服务**排序好，但要多一个服务、多一份要同步的索引，而且那份存储你没法 `git diff`。
- **笔记加一份指令文件**保持可读，但没有任何机制让 agent 在需要的那一刻去读它。一个没人打开的笔记本，
  只是被整理得很好的损失。

这个插件选第二种形态，补两件事：*什么时候去看*，和*什么时候去写*。

## 它做什么

1. **常驻索引。** 每条以"文件名 + 一行摘要"出现，摘要有固定长度上限。摘要是模型判断"这条值不值得读"的
   依据——文件名能引起一次读取，但阻止不了一次错误的读取。空笔记本注入**零字节**——整个小节消失。
2. **模型自己读它需要的。** 索引头部会告诉它：名字和你要做的事对得上，就用 `memory_read` 读它。
   **没有任何东西被自动注入**——原因见[它有多准](#它有多准)，想改成自动匹配就设 `recallEnabled`。
3. **七个工具**：读、写、认定、审计、诊断、记账。每次写入都必须带证据。

笔记本本身是普通 markdown：一个主题一个文件，`INDEX.md` 可选、只用来固定顺序，frontmatter 可选，
另有单独一条写着这个笔记本自己的规则。那条规则**随插件发布**，会播种到任何还没有它的笔记本里，
并且从不覆盖已经被改过的副本。为什么这么安排，见 [docs/architecture-en.md](docs/architecture-en.md)。

## 它有多准

这里测两件事，第二件就是自动召回默认关闭的原因。

**匹配质量**，在 29 条的笔记本上双向实测，判断集提交在 [`tests/qrels.json`](tests/qrels.json)：

| 查询集合 | 结果 |
|---|---|
| 用笔记本自己的说法提问 | 52/52 |
| 盲写的新说法，从处境出发 | 6/18 |
| `tests/qrels.json` 里的无关问题 | 24 条里触发 0 次 |

**然后是没人会为自己写的那一组**——只是和笔记本共享了词汇的日常话：

| 你打的字 | 它拉进来了什么 |
|---|---|
| 证书考试过了 | TLS 那条——"证书"也是考试证书 |
| 笔记本屏幕有点暗 | 笔记本规则那条——"笔记本"也是笔记本电脑 |
| 插件挺多的 | 两条插件记忆，来自一句什么都没说的闲聊 |
| **和笔记本共享词汇的日常话** | **18 条里触发 5 次** |

`qrels.json` 里那 24 条干净，是因为**写它们的人和写 trigger 的是同一个人**。这一组不是。

**把门槛提高分不开它们。** 正确召回和误召回都是 4–5 分，把下限提到 6，要用六条正确召回里的四条，换掉五条误召回里的四条：

```
分数 | 召回  | 误触发
  4  |  6/18 |  5/18
  5  |  6/18 |  5/18
  6  |  2/18 |  1/18
  8  |  1/18 |  0/18
```

所以默认为 Claude Code 的做法：**索引列出每一条，模型看到名字对得上就自己去读。** 没有匹配器，就没有误召回。

真开了自动匹配，它的本事也是词法层面的：它在比词。你用条目里已有的词描述问题，它就命中；
你描述**症状**而条目记录的是**机制**——你说"拍出来一片黑"，条目写的是"黑帧"——它就找不到。
这是 `recallEnabled: true` 会继承过来的边界。

## 和别的方案比

基于 2026 年对整个领域的一次调研：

| | 本插件 | Claude Code | engramory | OKF agent memory | EverOS |
|---|---|---|---|---|---|
| 依赖 | 无 | — | Python 脚本 | Go 二进制 | 服务 + LLM key |
| 读路径上的模型调用 | 无 | 无 | 无 | 无 | 有 |
| 强制来源 | **有**（`Evidence:`） | 无 | **无** | 可选 | 记录 |
| 信任状态 | **有** | 无 | **无** | OKF 分级 | 有 |
| 老化 / 审计 | **有** | 无 | **无** | `stale_after` | 有 |
| 自动召回 | 有（新说法约 20%） | **无** | **无** | codex + 索引 | 有 |
| 索引上限强制 | 无（溢出被计数） | 告警 | **有** | 评分卡 | — |

Claude Code 的 auto-memory 在**形态**上最接近——文件名索引、一个主题一个文件、细节按需打开。它
**刻意完全不做匹配**：模型看名字自己决定。本插件在它之上加了匹配，这是一点真实的便利，也是真实地弱。

`engramory` 形态相同，并且有本插件没有的强制手段（硬性索引上限、多宿主共享）。它自己列出的短板，
恰好是本插件的长处：没有来源、没有可信度、没有老化。

有一条比任何机制都值得说的发现：**这个领域里我核查过的每一个公开 benchmark 都经不起核查**——有的项目
报告召回率 +7.6 个点，而它自己的答案重放数字只动了一例；有的项目那个招牌数字在仓库里根本搜不到。
在自己语料上测。这里附带的判断集很小、诚实，而且只针对真正重要的那种情况。

## 安装

```sh
dsh plugin --profile <名字> add <这份代码的路径>
```

首次安装通过热重载生效。替换已安装的副本需要重启。

## 配置

在 profile 的 `cordis.patch.yml` 里 `memory` 那一行下面设置。这个 bundle 不声明 `Config`
schema，所以值按原样取用；下面的默认值写在代码里。

| 键 | 默认 | 含义 |
|---|---|---|
| `workspaceDir` | `.agents/memory` | 笔记本目录，相对于会话工作目录。`''` 关闭这一层。 |
| `machineDir` | `''` | 可选的机器级一层，绝对路径或 `~` 开头。重名时工作区那层优先。 |
| `showIndex` | `true` | 注入文件名索引。 |
| `indexBudgetChars` | `9000` | 索引里**列出多少条**的上限，不是笔记本能存多少条。超出的部分在索引里被计数，仍然可被召回。 |
| `indexSummaryChars` | `60` | 每个索引行里摘要的字符数，跟在文件名后面。`0` 退回纯文件名——条目更多，但每条的信息更少。 |
| `recallEnabled` | `true` | 为当前这轮发布匹配到的条目。 |
| `recallBudgetChars` | `1400` | 一次召回发布的字符上限。 |
| `maxRecall` | `2` | 一条消息最多发布几条。 |
| `minRecallScore` | `4` | 加权分数下限（trigger 短语 5–7、文件名 4、标题 3、正文 1）。 |
| `minRecallHits` | `2` | 必须命中的不同查询词数。 |
| `minQueryChars` | `6` | 更短的消息不触发召回。 |
| `skipAcknowledgements` | `true` | 只表示"收到/好的"的消息不触发召回。 |
| `captureHintRatio` | `0.6` | 上下文窗口用到多少比例时，提示一次"把值得记的先存下来"。`0` 关闭。 |

## 怎么写一条

一个主题一个文件。frontmatter 可选，`INDEX.md` 只用来固定顺序。

```markdown
---
status: verified
triggers: platformio, 固件, 烧录, 编译, 路径太长, 装不上, 编译 失败
---

# 一句结论，单独看也能用 — 2026-11-02

症状、机制、绕法。

Evidence: `能证明这件事的确切命令或报错原文`
```

- **`triggers`** 是召回词表，它决定这条记忆这辈子会不会被找到。写**你真的会说出口的词**，
  不要写说明书里的词：

  | 你会说 | 不要只写 |
  |---|---|
  | 换台电脑打开就不对了 | 转发、绝对路径、盘符 |
  | 浏览器能打开但命令不行 | curl、tls、schannel |
  | 拍出来一片黑 | 黑帧、白平衡 |
  | 它怎么没想起来 | 触发词、召回率 |

  多词短语只有在每个词都出现时才匹配——所以短语要具体（`dotnet pipe denied`，不是 `denied`）。
  避免**单个通用词**（`配置`、`权限`、`重启`）：它一旦配上第二个命中词，就会把这条拖进无关对话。
  也**不要用单个汉字**——它拿不到让匹配成立的那第二个命中。
- **`status`** 是 `candidate`（默认）、`verified` 或 `disputed`。`disputed` 的条目既不进索引也不召回。
- **`Evidence:`** 通过 `memory_write` 写入时必填。召回被压到预算时也是保留这一行而不是丢掉——
  一条没有证据的记忆读起来就是一个无法核实的断言。

## 工具

| 工具 | 用途 |
|---|---|
| `memory_list` | 名字、信任状态、标题——包括超出索引预算的那些。 |
| `memory_read` | 读一整条。 |
| `memory_write` | 建或改；`evidence` 必填。会回报这条是否在索引里常驻。 |
| `memory_verify` | 提到 `verified`，或作废成 `disputed`。 |
| `memory_audit` | 没有 `Evidence:` 的、长期没动过的、`INDEX.md` 两个方向的漂移。 |
| `memory_health` | 区分"记忆坏了"和"只是没有匹配上"：`ok`、`degraded`、`broken`、`absent`、`unconfigured`。 |
| `memory_usage` | 哪些条目被召回出版过、哪些从来没有。只记条目名和日期，不记你的提问。 |

## 为什么省

按**每一条**算，不是按整个笔记本算——总量会涨，这个单价不涨：

| 成本 | 值 |
|---|---|
| 每轮索引里的一行 | 约 34 字符、约 10 token |
| 一次召回发布 | 最多 `recallBudgetChars`，默认约 390 token |
| 空笔记本 | 0 字节 |
| 读路径上的向量 / 模型调用 | 无 |
| 后台整理 | 无 |

这个预算是一个**旋钮，不是天花板**。1400 字符大约常驻 34 条，700 大约 10 条。两种情况下容量都没有上限：
超出预算的条目在索引里被计数、仍可被召回、`memory_list` 能列出来。见
[ADR 0014](docs/adr/14-index-budget-is-residency.md)。

## 出问题的时候

- **所有 `memory_*` 工具都报 `unknown tool`。** 插件没加载起来。几乎总是某个工具 schema 被宿主拒绝——
  宿主在加载时校验 schema，拒绝的是整个插件，不是一个工具。查宿主日志；它执行的规则已经抄进
  `tests/core.test.mjs` 的 *every tool schema stays inside the host subset* 一节。
- **记忆从来不触发。** 先调 `memory_health`。它把"坏了"和"没有匹配上"分开——这两个状态从一个返回空
  的查询里看起来一模一样。如果它说 `ok`，笔记本是好的，问题在词表。
- **写进去了但索引里没有。** 它超出了 `indexBudgetChars`。`memory_write` 已经在 `indexOverflow`
  里说了；`memory_usage` 会告诉你到底有没有东西读过它。
- **记忆不再被保存。** 笔记本目录不可写。`memory_health` 会专门报告这一条——它是那种"看起来一切正常"的故障。

## 验证

```sh
node tests/core.test.mjs                 # 行为检查，零依赖
node scripts/eval-recall.mjs       # 基于 tests/qrels.json 的召回判断
node scripts/check-paths.mjs       # 任何文档里都不出现机器特定路径
node scripts/check-docs.mjs         # ADR 已登记、语言切换、链接可达
node scripts/check-evidence.mjs --dir tests/fixtures/notebook
node scripts/check-index.mjs --dir tests/fixtures/notebook
```

CI 跑全部这些，挂了就不许合并。覆盖范围：笔记本发现与 `INDEX.md` 排序、索引常驻与计数溢出、空笔记本行为、
拉丁与中日韩分词（含中英粘连）、确认语闸门、中英文召回、整短语与唯一性加权匹配、信任状态转换、
disputed 条目同时从索引和召回消失、证据完备与老化、使用记账、能力诊断、宿主 API 守卫，
以及宿主自己的工具 schema 规则。

## 接受的设计限制

- **词法匹配，而这就是硬上限。** 当问题用的是笔记本里没有的词，大约五次里有一次能找到。这是有意的取舍：
  另一条路要么多一个服务、要么每轮一次模型调用，而公开证据并不支持它们真能换来答案质量。
  解法在词表，不在算法——见[怎么写一条](#怎么写一条)。
- **不自动捕获。** 闭环全靠模型自己决定调 `memory_write`。压缩前会提示一次；那和"自动记下原始事件"
  不是一回事，这里也不这么宣称。
- **没有"已注入上下文"的可见行。** profile 链接的 bundle 不能 import `@deepseek-ai/*`
  （[ADR 0001](docs/adr/01-zero-dependency-host-half.md)），所以召回走运行时上下文通道而不是伪造一条用户消息。
  好处是：不进会话日志，而且能扛过压缩。
- **默认没有跨工作区那一层。** `machineDir` 就是为它准备的；不配置就不开，重名时工作区那层优先。
- **`verified` 没有被强制。** 模型写下的都是 `candidate`，直到有东西把它提上去——而模型可以提自己的条目。
  它是一个信号，不是"人工审核过"的证明。
