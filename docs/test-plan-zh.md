# 测试计划

> 英文版：[test-plan-en.md](test-plan-en.md)。**英文版是权威**。

> 维护者：@FrozenYty · 何时重看：新增一层测试，或某个"保证"不再成立时

测了什么、在哪一层测、以及最常被省略的那部分——**这些加起来仍然证明不了什么**。最后一节正是这份文档
存在的理由：**一套被信任到超出其射程的测试，比一套更小但被正确看待的更糟。**

## 1. 分层

五层，从最便宜的开始。每一层回答的是下一层答不了的问题。

| 层 | 命令 | 回答 | 耗时 |
|---|---|---|---|
| **行为** | `node tests/core.test.mjs` | 代码是否按 ADR 说的做？ | 约 1 秒 |
| **召回判断** | `node scripts/eval-recall.mjs` | 某条提问是否到达人认定的那条条目？ | 约 0.5 秒 |
| **敌意提问** | `node scripts/eval-hostile.mjs --dir tests/fixtures/notebook` | 与笔记本共享词汇的日常闲聊，是否保持沉默？ | 约 0.5 秒 |
| **变异扫描** | `node scripts/mutation-scan.mjs` | 某一行被改坏时，测试会不会发现？ | 约 2 分钟 |
| **断言强度** | `node scripts/assertion-strength.mjs` | 这个断言有没有可能失败？ | 约 0.2 秒 |

另有六个**闸门**检查文档与历史而非行为：`check-docs`、`check-paths`、`check-evidence`、`check-index`、
`check-commit-messages`，以及对两个源文件跑 `node --check`。它们全部在 CI 里运行并阻止合并。

## 2. 每层装了什么

### 行为层 —— `tests/core.test.mjs`

**22 节共 184 项检查**，只针对 `tests/fixtures/notebook`：一个需要仓库外数据的测试在本机能过、在 CI 会挂，
这正是夹具出现之前发生过的事。

| 节 | 覆盖 |
|---|---|
| 1 | 发现、索引构建、预算、空笔记本 |
| 2 | 分词、确认门、前缀门槛 |
| 3–4 | 英文与纯中文提问的召回 |
| 5 | 渲染守住预算且不丢 `Evidence:` |
| 6 | 信任状态、写入、frontmatter 保真 |
| 7 | 证据卫生、语言、重复的证据行 |
| 8 | 索引漂移，两个方向 |
| 9 | 政策播种，且永不覆盖 |
| 10–11 | 误报预算；粘连的混排输入 |
| 12–13 | 索引是派生的；预算限制常驻条数而非容量 |
| 15 | 健康检查：坏掉不等于为空 |
| 16 | usage 日志格式，以及从塌成一行的文件里恢复 |
| 17–18 | 工具 schema 在宿主子集内；宿主 API 守卫 |
| 19–20 | 畸形条目仍能加载；读取会被计数 |
| 21–22 | 路径解析与去重；每个目录都被播种和同步；日期用本地日历 |

### 召回判断 —— `tests/qrels.json`

**52 条相关 + 24 条无关**，每条写明必须最先命中的是哪条条目，或者什么都**不许**触发。由作者手写，
不是抓来的：要回答的是"这条规则是否符合人的相关感"，而不是"它比另一个实现排名高多少"（ADR 0011）。

**翻转一个用例是一个结果，不是副作用**——要么改规则，要么有意改判断。

### 敌意提问 —— `tests/hostile.json`

**18 个用例，16 个期望沉默**，每个都附了理由。这一层**目前是失败的**——18 个里有 4 个触发——而这个失败
正是 `recallEnabled` 默认为 `false` 的成文理由（ADR 0015）。**它不进 CI 就是因为这个**：它是一次测量，
不是一道闸门。

### 变异扫描 —— `scripts/mutation-scan.mjs`

**73 个变异，73 个被杀死。** 每个变异按"一个合理的错误写法"改坏一行，然后跑完整测试集。存活意味着没有
测试发现它——要么是未覆盖的行，要么是等价变异，**扫描器分不清这两者**。

扫描器在每个变异后用 `finally` 恢复两个源文件，结尾再整体校验一次；调用方另外用 SHA256 和备份比对。
**一个会改源码、崩了就留下坏文件的工具，比没有更糟**——所以恢复不是 `catch` 而是 `finally` 加一次校验。

**变异未应用时它退出 1**，因为**一个测的比它声称的少的扫描器，是最安静的撒谎方式**。

### 断言强度 —— `scripts/assertion-strength.mjs`

**解析 164 个断言，2 个可疑，且两个都合理。** 它找的是"不可能失败"的断言：字面量、只判 `!== undefined`、
只判非空、恒真。它负责标出，人负责判断——`x === true` 是强是弱，取决于 `x` 是什么。

## 3. 支撑这套分层的那个实例

39 个变异的扫描曾报告 **39 被杀死、0 存活**，而当时五个修复中有两个毫无保护。把代码退回修复前，测试全绿：

| 缺陷 | 回退后被抓到？ | 原因 |
|---|---|---|
| 更新会抹掉 `summary` | 是，4 项测试 | 断言的是内容 |
| 未知 frontmatter 键被丢弃 | 是 | 同上 |
| 同一目录配两次被计数两次 | 是，1 项测试 | 断言的是一个计数 |
| **日期用的是 UTC** | **否** | 在 11:30 跑，那时 UTC 与本地同一天；它只在本地 00:00–07:59 才能区分 |
| **只播种/同步了第一个目录** | **否** | 测试只配置过一个目录 |

两个缺口都补上了——日期用**静态守卫**（时钟绕不过去），多目录通过真实触发 `systemPrompt.section` 回调。
现在把代码退回修复前，扫描报告 **8 项失败**。

**教训就在这些数字里**：测试全绿和测试有意义是两个不同的测量，而此前只报告了第一个。

## 4. 这些加起来证明不了什么

- **73 个变异对约 950 行代码是抽样。** 它说明它碰到的每一处构造都有防护，**不说明没碰到的部分也是**。
- **断言检查器判断不了意图。** 它找可疑形状，不找错误断言。
- **两个工具都找不到"没人想到去破坏"的 bug。** 它们量的是测试，不是插件。
- **行为测试不是类型检查。** `node --check` 只看语法，文档闸门从不看 JavaScript。
- **召回质量是在夹具上量的，不是在作者真实笔记本上。** 夹具是故意冻结的（它的 `README.md` 说明了原因），
  所以在那里成立的规则，在真实笔记上仍可能误触发。
- **这里没有一样在测 DSH 本身。** 宿主的 schema 校验器、提示通道和事件名都被当作既定事实；ADR 0001 解释了
  为什么它们既不能被 import，也就不能被断言。

## 5. 什么时候算"测试写完了"

只有一条：**把修复回退，看测试会不会挂。** 不能失败的测试是装饰品，而变异扫描之所以存在，正是因为
**读一遍测试是看不出它属于哪一类的**。

推论：**没有做这一步就汇报"已修复"，那是猜测。** §3 里的两个缺陷在回退之前，都已经被"修复并测试过"了。
